Graph Theory Essentials and Java Implementation Guide

1. Introduction to Graph Fundamentals

In computer science, a Graph is a non-linear data structure used to represent complex relationships between objects. Based on the source material, a graph is defined by two primary components:

* Nodes (Vertices): These are the entities in the graph, typically visualized as circles and represented by numbers.
* Edges: These are the lines connecting two nodes, representing a relationship or a path between them.

Note on Labeling: There is no specific mathematical order required for numbering nodes. For instance, in a graph with five nodes, they can be labeled 1 through 5 in any arbitrary spatial arrangement.

2. Categorization of Graph Types

Directed vs. Undirected Graphs

The nature of the connection between nodes defines the graph's directionality.

Feature	Undirected Graph	Directed Graph
Edge Visualization	Simple lines.	Lines with arrows indicating direction.
Directionality	Bi-directional: An edge between u and v implies u \to v AND v \to u.	One-way: An edge u \to v does not imply a return path from v to u.
Logic	If you can go from 1 to 2, you can go from 2 to 1.	Movement is restricted to the arrow's direction.

Cyclic vs. Acyclic Graphs

* Cycle: A cycle is a path that starts at a specific node and ends at that same node.
* Undirected Cyclic Graph: An undirected graph that contains at least one cycle.
* Directed Acyclic Graph (DAG): A directed graph that contains no cycles. This is a crucial structure in algorithms like Topological Sort.

Expert Insight: Trees as Graphs A graph does not need to be an "enclosed" or "circular" structure. A Binary Tree is technically a graph because it consists of nodes and edges. It is simply a specific type of acyclic graph.

3. Key Graph Properties and Definitions

Path Definition

A path is a sequence of nodes where:

1. Each node is reachable from the previous one.
2. Adjacent nodes in the sequence must have a physical edge connecting them.
3. Uniqueness: A node cannot appear more than once in the sequence.

Technical Synthesis: If a sequence violates the uniqueness rule by starting and ending at the same node, it transitions from being a simple path to being defined as a cycle.

Degree of a Node (Undirected)

The degree is the total count of edges connected to a node.

* Mathematical Property: Total Degree = 2 \times \text{Number of Edges}.
* Intuition: Because every edge connects two nodes, each edge contributes exactly "2" to the total degree count of the entire graph.

Degrees in Directed Graphs

Directed graphs split the concept of degree into two metrics:

* In-degree: The number of edges pointing into a node (incoming).
* Out-degree: The number of edges pointing away from a node (outgoing).

Edge Weights

Edges can carry values known as weights (e.g., representing distance or cost).

* Default Convention: If a problem does not specify weights, we assume a unit weight of 1 for every edge.

4. Standard Input Format

In competitive programming and technical interviews, graph data is typically provided in a standardized format:

1. The First Line: Contains two integers, N (number of nodes) and M (number of edges).
2. The Next M Lines: Each line contains two integers u and v, representing an edge between those nodes.

5. Java Representation: Adjacency Matrix

Structural Logic

The Adjacency Matrix uses a 2D array: int[][] adj = new int[n+1][n+1]. We use n+1 to allow for 1-based indexing, making the code more readable by matching the node labels 1 to N.

Storage Protocol

For every edge (u, v) in an undirected graph, we mark the connectivity in both directions:

// For an edge between u and v
adj[u][v] = 1;
adj[v][u] = 1;


A 0 in the matrix indicates no edge, while a 1 indicates an existing edge.

Analysis

* Space Complexity: O(N^2).
* Expert Evaluation: This is memory-intensive. It is only suitable for small graphs (typically N \le 10,000) because it allocates space for every possible connection, even those that don't exist.

6. Java Representation: Adjacency List

Structural Logic

This is the preferred professional method. We use a collection of lists, where each index i represents a node, and the list at that index contains all its neighbors. In Java, this is implemented as an ArrayList of ArrayLists: ArrayList<ArrayList<Integer>> adj = new ArrayList<>();

Storage Protocol

First, initialize the list with N+1 empty internal lists. Then, add the edges:

// For an undirected edge between u and v
adj.get(u).add(v);
adj.get(v).add(u);


Analysis

* Space Complexity: O(V + 2E), where V is the number of vertices and E is the number of edges.
* Efficiency: We spend O(V) to initialize the list headers and O(2E) to store the actual neighbors. This is far more efficient than the matrix for "sparse" graphs (graphs with fewer edges).

7. Special Implementations

Directed Graphs

In a directed graph, the storage protocol is modified to respect the one-way nature of the edge.

* Matrix: Only adj[u][v] = 1;
* List: Only adj.get(u).add(v);

Weighted Graphs

To store weights, we move beyond simple boolean indicators:

* Matrix: Instead of storing 1, store the weight. adj[u][v] = weight;
* List: Instead of an ArrayList<Integer>, we store a list of objects. Since the Java standard library does not include a generic Pair class in the java.util package, experts typically define a custom Node or Edge class:

class Node {
    int target;
    int weight;
    Node(int t, int w) {
        this.target = t;
        this.weight = w;
    }
}

// Implementation
ArrayList<ArrayList<Node>> adj = new ArrayList<>();
adj.get(u).add(new Node(v, weight));


Using a custom class is preferred over library-specific pairs (like JavaFX) to ensure the code remains portable and clear during technical evaluations.
